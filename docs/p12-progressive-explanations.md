# P12 设计详解：协议桥接、连接寿命与能力代次

配套[架构正文](p12-progressive-guide.md)。官方 SDK 管传输，框架适配已有工具契约，宿主管连接作用域。

<a id="p12-a1"></a>
## A1：Adapter 只吸收协议差异

MCPTool 是 Tool 的适配实现，Registry 继续负责名称、Policy、breaker 与统一结果，Runtime 继续控制模型/工具往返。无需为远端工具另建一套 Agent 循环。

MCPConnection 接受 stdio 参数、Streamable HTTP URL 或 SDK 传输对象，后者可携认证配置。桥接当前只自动注册工具，不能据类名推导 resources/prompts 同样自动进入模型。

<a id="p12-a2"></a>
## A2：连接不能与纯业务对象一样任意共享

Client 绑定当前事件循环；MCPTool.arun 首先检查 owner loop。P11 fork 共享工具对象并不会改变连接所有者，Task 子线程中的新循环也无法直接借用它。

因此 MCP 场景使用宿主同一 async with/事件循环里的 arun 或异步流。同步工具入口明确抛错，Registry 可能把错误包装成统一回执；不能声称同步入口会自动创建另一套远端连接。

<a id="p12-a3"></a>
## A3：目录协商是资源准入的一部分

连接进入后一次性遍历目录并校验，避免请求时才发现重名或缺工具。分页 cursor 的 seen 集合阻止服务端重复游标导致无休止循环；名称限制保护统一工具接口。

失败用 __aexit__ 清理已打开 Client。register_tools 先检查整个导出集合与本地撞名，不静默替换宿主已有定义；prefix 是名称空间约定，不是执行权限，真正许可仍由 Policy 决定。

<a id="p12-a4"></a>
## A4：Schema 原样保留与运行前验证协作

MCPTool.get_parameters 返回空列表，实际模型 Schema 由覆写方法提供完整 inputSchema，保住嵌套结构和本地引用。jsonschema 检查定义并在 arun 前验证 dict 参数，错误不触发远端调用。

禁止非片段 $ref/$dynamicRef，避免工具参数契约悄悄依赖外部解析。这里验证 JSON Schema，不把所有远端行为安全性归结为参数合法。

<a id="p12-a5"></a>
## A5：保留原始协议结果防止信息压扁

text 仅由文本块连接；结构化字段和图像等块保留在 data.mcp。isError 是远端执行结果，与本地参数校验失败、网络异常、宿主拒绝分属不同边界。

桥接不自动重试 call_tool。远端写入可能已提交而响应迟到，重试会重复副作用；P04/P09 的 unknown 原则同样适用，网络失败不能证明业务未发生。

<a id="p12-a6"></a>
## A6：拥有注册对象才拥有清理权

连接保存自己注册的对象身份，退出时若宿主已替换同名工具，就保留新对象。仅按名字清理会误删宿主改动，也无法表达共享 Registry 的生命周期。

fork 本身不新增连接所有者，不能由子任务替宿主关闭。连接退出只清理直接登记的注册项；其他引用通过开放/循环/代次检查失效。

<a id="p12-a7"></a>
## A7：generation 是能力寿命的身份

连接对象身份不变，但每次建立的会话不同。MCPTool 保存 generation object，用身份比较隔离旧能力，避免同名工具在重连后无意访问新的允许目录。

这是一种代次校验，范围限于本进程连接对象，不是分布式租约或远端幂等令牌。它不回滚之前真实调用，也不证明远端事务取消。

<a id="p12-a8"></a>
## A8：真实传输与协议故障各提供一半证据

实际 stdio/回环 HTTP 证明 SDK、Server、目录和调用能协作；目录替身能稳定构造重复 cursor、名字、缺允许项和外部引用。两者组合避免只有 Mock 或只覆盖成功示例。

当前依赖按固定 uv.lock 递归补齐，示例只用 fixture 数据。讲解验收：循环为何属于连接？清理为什么看对象身份？旧 fork 名称还在时谁拒绝调用？structuredContent 到哪里？超时为何不能盲重试？
