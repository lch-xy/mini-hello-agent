# P19 设计详解：将复刻一致性、可用性与学习理解分开证明

对应[架构递进](p19-progressive-guide.md)。最终状态与证据见[实现记录](p19-learning-record.md)。

<a id="p19-a1"></a>
## A1：固定对象是范围权威，测试是行为证据

当前目标不是泛化的“Agent 框架”，而是固定 commit 的有限集合。81 个 Python 文件/类型标记确定框架边界；公开导出确定用户可用入口；原测试、示例、资源与打包规则确定消费环境。Git 历史解释早期图驱动、后续本地 Runtime 与当前组件组合的变化，不把提交标题当作完整设计理由。

最终 76 个框架文件逐字节一致，6 个 P01 注释模块排除字符串说明和导入组织后可执行 AST 一致；保留注释是你的明确要求。字节比较证明来源一致，不能代替运行；行为测试证明已检查路径，不能证明所有现实语义。

<a id="p19-a2"></a>
## A2：依赖分层对应实际装配选择

核心只提供 Agent、数据契约与本地存储所需依赖；MCP/Web/向量/GraphRAG/其他协议等由八个 extras 选择。quality 是开发检查工具，构建 backend 的 setuptools/wheel 属于发行环境。这样最小消费者无需为没使用的能力承担全部 SDK。

pip 全功能环境由目标 all.txt 安装，quality 精确版本按目标锁文件闭包安装。原 uv.lock/全部 requirements 导出均保留；使用临时固定 uv 0.12.23 离线核对 lock --check 与原 sync_requirements --check，没有把项目安装路线切换到 uv，也没有让导出成为另一套解析输入。

Python 建议只提示推荐 3.13，支持范围仍为 >=3.12,<3.14；导入不修改宿主 logging 的级别。SDK 构造验证不发请求，真实服务能力需另行显式配置。

<a id="p19-a3"></a>
## A3：测试归并以断言保留为条件

阶段提取的定义逐一与完整原文件 AST 比较，只有全部类/函数定义已在原文件中存在才移除；本次移除 34 份。原 45 个模块齐全，其中 context_engineering 只增加在 tmp_path 内执行的 fixture，避免示例产物污染仓库；所有原定义仍相同。

保留 18 个新增阶段实验，包括四入口与取消、真实文件副作用、HTTP 断连、嵌套 MCP、Task 父状态、存储 namespace、记忆过期边界、重排/索引失败、非收敛归约和预算流中断。最终 700 passed/12 skipped 与之前数量不可直接比较，覆盖率和范围清单共同说明结果。

<a id="p19-a4"></a>
## A4：在消费入口验证模块组合

完整 current_examples 测试在独立目录执行每个可离线公开案例，阻断模型 HTTP；云端缺配置、.env 优先级、SDK 关闭与多个自定义工具模板也有原断言。原 runtime_features_example 执行七篇文档的实际 Python 片段。Web 原生流、真实 HTTP 断开与 MCP stdio/HTTP 在相关测试中运行。

这些覆盖 SDK 模拟响应、真实 Runtime、实际 SQLite/Qdrant/Leiden 和传输生命周期。真实模型质量、云账号、FastEmbed 权重后的语义排序均不由离线结果证明。应用示例中的旅行资料为固定虚构材料，测试的是状态与引用契约。

<a id="p19-a5"></a>
## A5：由变化选择修改位置，而非套设计模式名单

| 变化 | 应先修改 | 保持稳定的契约与必要验证 |
| --- | --- | --- |
| 新模型协议 | Adapter 和选择入口 | 模型响应/工具消息；工具往返、流关闭、usage |
| 更换召回 | SearchBackend/Provider 装配 | evidence 身份与上下文角色；过期、范围、回读 |
| 新执行策略 | Agent 策略编排 | Runtime 工具执行、生命周期；四入口与终止状态 |
| 修订偏好 | 对应 Memory/Profile Store 动作 | 身份、revision、来源；下一请求刷新与并发冲突 |
| 后台重试 | handler 幂等与 checkpoint | 队列租约、发布边界；旧 owner 与迟到副作用 |

Facade/Adapter 让协议变化留在模型层；策略与共享 Runtime 分离让执行机制集中；协议注入让上下文和检索可组合；Store 集中持久化不变量；CAS 与租约表达不同类型的当前有效性。不存在一种模式可以替代来源校验、业务授权或外部幂等。

<a id="p19-a6"></a>
## A6：发行验收必须切断源码路径的帮助

本次按 pip 路线调用目标 pyproject 指定的 setuptools backend，sdist 解包后再构建 wheel，核对 81 个 Python 文件字节与 py.typed。新 venv 只安装 wheel/核心依赖，在外部目录用 -I 运行真实 RAG、Memory、JobQueue；确认 MCP/Qdrant/igraph 没有安装却能导入基础包。

MANIFEST 控制 sdist，setuptools 包发现控制 wheel，两者不同；根 skills 不会自动装进 wheel。学习仓库保留 131 个资源供显式路径读取，README 增加学习导航，保留作者与许可。没有发布到 PyPI；Git 远端仓库与本地发行验证是当前交付范围。

<a id="p19-a7"></a>
## A7：各质量证据回答不同问题

Ruff 用目标 E9/F63/F7/F82 规则，不无故扩展风格重排；coverage 包含分支，85.16% 超过 82%，仍有未覆盖行可查看报告。多进程脚本验证 200 个唯一完成、一次进程退出恢复和异 namespace 不变，不冒充生产吞吐基准。pip-audit 检查 all.txt 的公开固定依赖，当前 82 项无已知漏洞、无跳过；不覆盖未来公告或未扫描的构建工具。

本机 ONNX 遥测退出问题按 P15 证据处理：测试启动前关闭遥测，进程退出码真实检查。覆盖率启动器放在临时独立目录，并显式加入仓库根目录供 examples 使用，断言 hello_agents 来自复刻路径；正式 wheel 验证另用 -I 切断该路径。未执行远端 Windows/Linux 全矩阵，不把已保存 CI 配置称为已运行结果。

<a id="p19-a8"></a>
## A8：开发完成与理解完成有独立验收

开发完成要求有限清单、运行行为、发行、质量、提交与远端一致；学习完成要求你能解释为何这样分层、替代方案的代价、需求改变时该改哪里。P00 实验按你的要求免验，其余测试通过不会替你回答理解题。

建议下一轮只选一个完整变化，例如“偏好 8→5 后后台语义索引失败并重试”：先画状态拥有者和失效条件，再根据各阶段 A1～A8 解释选择，最后用现成案例观察证据。这样从已有架构推演变化，不需要重新回到逐行记忆源码。
