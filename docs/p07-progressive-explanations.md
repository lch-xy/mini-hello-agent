# P07 设计详解：配置默认、显式覆盖与所有权

配套[架构正文](p07-progressive-guide.md)。目标是把依赖显式交给对象，不扩展成通用依赖注入平台。

<a id="p07-a1"></a>
## A1：装配入口使变化集中

配置表达“默认要不要启用”，组件表达“实际用哪个实现”。两者都存在时，需要一个明确解析点，而不是在四种 Agent 里各写一套条件。

Agent 基类调用 build_agent_components，策略构造只透传 components。新增宿主历史实现时，变更停留在装配处，Runtime 和模型适配不需要了解它的数据库、缓存或对象层级。

<a id="p07-a2"></a>
## A2：Protocol 描述消费方需求

Protocol 让宿主通过组合而非继承提供能力。接口应由 Agent 实际调用决定：Counter 需要单条/列表计数与清缓存，Truncator 只需 truncate，历史则还需要保留轮次边界。

运行时还用 _METHODS 检查可调用方法。它不是完整类型证明，也不验证所有签名或行为；后续真实运行测试提供证据。ResolvedAgentComponents 的 frozen 只防止字段重新赋值，内部历史/存储对象仍可变。

<a id="p07-a3"></a>
## A3：哨兵值保留用户意图

可选组件需要区分“我没指定”“我明确关闭”“我提供实现”。如果默认和关闭都用 None，Config 开启时就无法显式禁用；如果使用 value or default，又会丢掉合法假值对象。

DEFAULT_COMPONENT 用身份判断代表未覆盖，None 明确禁用，实例按身份保留。必需组件没有禁用态，None 创建默认实例。这是字段各自的契约，不是全项目统一的 None 语义。

<a id="p07-a4"></a>
## A4：验证顺序减少构造副作用

先检查所有覆盖，再创建默认目录，能保证常见注入错误在资源创建前暴露。但宿主传入实例本身已经发生的构造行为不归此函数撤销；工具注册阶段后续失败也不是事务回滚。

因此准确保证是“组件协议验证先于默认资源创建”，不能扩大为“任何构造失败都绝无副作用”。测试明确只观察这一边界。

<a id="p07-a5"></a>
## A5：借用状态需要保持对象身份

预加载历史可能已经属于宿主会话，初始化不能偷偷清空。组件自带 min_retain_rounds 应同时控制摘要输入和保留尾部；否则摘要掉的范围与实际删除范围会错位。

默认新建对象自然隔离，显式共享对象则由宿主承担协调。模型/组件的生命周期也由宿主管理，Agent 不在一次任务结束后关闭传入模型。会话并发保护仍是 P04 的 _run_active，不是对全部共享对象的线程锁。

<a id="p07-a6"></a>
## A6：完整模型依赖避免隐含配置继承

独立模型可能来自不同服务，名称不足以确定地址、密钥、协议和超时。目标要求直接注入完整可调用对象，默认回退主模型，而非拼接若干字段猜配置。

当前没有对注入模型强制 HelloAgentsLLM 具体类型；宿主可提供兼容对象，并负责其方法、连接与关闭。P18 才在实际完整 LLM 对象中接通共享预算，不能把 Mock 身份测试当作费用或服务可用性验证。

<a id="p07-a7"></a>
## A7：功能注册与组件解析属于不同步骤

有 SkillLoader 不一定自动注册 Skill，skills_auto_register 仍可关闭；有 Registry 才有注册目标；同名已有工具优先保留。构造默认 Agent 不应因可选模块存在就自动启用功能。

P07 用真实默认组件验证构造三态，但不提前运行尚未接入的技能/任务工具。完整原测试中的可选工具装配、Skill/Session 真正读写、子任务恢复三类组合会在对应阶段恢复，这种范围差异保留在记录中。

<a id="p07-a8"></a>
## A8：最小装配机制已满足当前变化

这里采用构造注入与组合，没有全局容器、服务定位器、自动扫描或生命周期托管。高内聚来自解析规则集中在 components，低耦合来自策略只消费实际能力；不能只凭 AgentComponents 类名宣称完全解耦。

讲解验收：None 在必需/可选字段分别意味着什么？假值实例为何不能用 or？何时创建目录？哪些状态必须保留？谁关闭模型？未来更换历史后端应该改哪里？回答时应能给出一次具体替换的实际调用路径。
