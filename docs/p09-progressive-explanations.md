# P09 设计详解：快照、执行证据与观察出口

配套[架构正文](p09-progressive-guide.md)。会话、Trace 与 SSE 围绕同一次执行协作，但保存目标和资源所有权不同。

<a id="p09-a1"></a>
## A1：快照是数据契约

序列化完整对象会把服务连接、锁、宿主回调和代码版本绑定在一起。显式 JSON 让数据范围可见，模型与工具仍由宿主重建；原生 model_message 保留 tool_calls 与 tool_call_id，避免只恢复文本却失去执行证据。

这属于状态快照与继续对话，不是恢复协程指令位置。配置只保存当前摘要字段，不复制全部 Config、密钥或工具源码，也不能证明外部环境完全相同。

<a id="p09-a2"></a>
## A2：保存完整性与写者协调分开

NamedTemporaryFile 提供本次独占名称，JSON 写完后原子替换，失败时只删该临时文件。Store 实例内 Lock 仅串行 replace，避免共享实例的替换竞争；不同实例/进程仍可能写同名目标，最终版本由替换顺序决定。

session_name 禁止目录分隔符等，控制的是保存/删除名称。load 接受宿主给出的文件路径，不因此获得文件系统沙箱。此保存实现也不能借用 P08 的 fsync 保证；应按本模块实际操作理解。

<a id="p09-a3"></a>
## A3：恢复先校验后替换

Message.from_dict、metadata/cache 顶层类型和计数在修改当前状态前完成；常见错误不会先清空已有历史。恢复空 read_cache 会覆盖旧缓存，防止另一会话的读取证据残留。

当前并未定义完整版本化快照迁移体系，也未深度校验 cache 每个值。不能把注释中的“完整快照”扩大成任意字段严格验证。活动运行不能 load，因为它会与 Runtime 修改同一历史。

<a id="p09-a4"></a>
## A4：接口指纹提供变化信号

按工具名排序使注册顺序无关，稳定 JSON 包含 description、parameters 等，函数与对象工具一起参与。改描述也会变哈希，因为它会影响模型理解；改函数内部实现未必变哈希。

一致性检查以提示为主，不自动迁移或重建工具。宿主决定在新环境重新读取、确认副作用或继续；指纹不能取代业务版本与外部幂等记录。

<a id="p09-a5"></a>
## A5：确认回执是恢复依据，不能替代幂等机制

SimpleAgent 在完成事件之前提交完整交互与统计，自动保存发生在这个边界；finally 对未完成轮保留确认结果并补 unknown。四策略中断测试使用真实写入和新 Agent 加载，后续脚本模型据已有回执回答，不再请求写入。

测试不证明任意模型都不会重复请求。Runtime 只校验当前批次 ID，不维护跨运行的业务去重账本。unknown 仍需核实外部状态；取消等待不能证明写入没发生。

自动保存捕获失败、按 debug 配置显示；手动保存抛错。因此“已启用自动保存”不等于每次运行都已持久化成功，重要场景应核对保存结果。

<a id="p09-a6"></a>
## A6：脱敏、HTML 转义与展示开关不是一件事

递归脱敏处理已知键和字符串模式，自定义 sanitizer 在 sanitize 开启时进一步处理；HTML escape 防止动态字段作为标签执行；html_include_raw_response 只控制 HTML 里是否展示该键，JSONL 仍保存经过脱敏的事件。

统计来自 model_output 的 usage/cost 和 tool_call 事件，不自行查询价格或把所有文本都当公开回答。Logger 同步写文件，I/O 失败仍可能传播；它不像生命周期回调那样有独立的异常隔离保证。

finalize 重复调用安全；后续 log_event 明确拒绝。SimpleAgent 下一次运行发现旧 Logger 已关闭会新建，因此同一 Agent 的多轮追踪有各自文件。

<a id="p09-a7"></a>
## A7：出口的异常处理必须覆盖已产出的事件

Web 默认每请求创建独立依赖，因而 finally 关闭模型合理；普通 Agent 只借用宿主模型，不在一次 run 后关闭。真正的 HTTP 断连会取消消费，aclosing 将关闭传播回模型源。

目标 Web 在 except 中产生统一错误，但此前会直接转发 Agent 产出的 ERROR。合成 RuntimeError 已观察到原始 error 字段先到、统一 message 后到；外层 try/except 无法收回已经发送的数据。这是目标现有行为，本阶段未擅自修改，记录供后续独立改进。

浏览器的停止仅表示停止接收及触发关闭，不代表同步线程副作用回滚。默认 Web 演示也没有开启会话持久化，不能把 HTTP 断连恢复等同于浏览器自动续跑。

<a id="p09-a8"></a>
## A8：验证要同时覆盖数据、生命周期与出口

文件可打开只证明格式，最后文本正确只证明某个输出，HTTP 200 也不证明任务 completed。当前验收同时检查历史回执、实际写入、元数据/缓存、终态、JSONL/HTML 和连接关闭。

Web 使用固定目标锁文件的依赖，测试原生 ASGI 接口和真实回环 HTTP；未将浏览器手工外观检查或真实模型服务列为通过。讲解验收：快照里有哪些东西？哪些依赖不保存？自动保存失败怎么办？raw_response 隐藏影响哪种输出？为什么统一错误捕获仍可能透传原始事件？
