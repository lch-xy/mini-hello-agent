# P05 设计详解：策略扩展点、阶段与共同执行

配套[架构正文](p05-progressive-guide.md)。以目标实现的控制权和取舍为依据，不把“有设计模式”当作质量结论。

<a id="p05-a1"></a>
## A1：继承生命周期，组合执行能力

SimpleAgent._events 具有模板式生命周期：建立工作状态、运行策略、提交、发事件、收尾。Reflection/PlanSolve 只覆写策略段，继续组合 turn_events、Planner/Executor 等能力。类的策略角色不等于实现了一个额外的 Strategy 接口体系。

高内聚意味着阶段规则留在各策略，协议细节留在适配器，实际业务留在工具。低耦合并非没有协作：Runtime 仍检查 _parallel_tools、_builtin_tools 并调用策略钩子。这是当前真实扩展点，不应描述成完全与策略无关。

<a id="p05-a2"></a>
## A2：控制工具改变的是运行状态

Thought/Finish 使用和业务工具相同的 ToolCall DTO，但由 ReAct 内部处理。Finish 能终止本批后续操作，因此不能像普通“返回字符串的工具”一样随意并发执行。先按返回顺序处理含控制工具的批次，可以明确哪些操作发生在结束前。

Thought 的 reasoning 参数是可观察的简短行动说明；模型服务商私有 reasoning_content 是协议字段，两者来源与公开边界不同。不要把 Thought 定义为自动提取模型内部推理。

<a id="p05-a3"></a>
## A3：并发成功与批次成功不是同一件事

同批工具有快有慢。若只在 gather 完整返回后保存回执，一个兄弟任务超时会抹掉其他已成功结果。目标在每个任务取得结果时通过 on_result 立即写入消息和统计，再在批次失败后取消其余等待者。

semaphore 约束正在执行数量，failed 标记阻止排队者在失败后进入业务。已经进入同步线程的操作仍遵守 P04 的晚到副作用边界。并发可以改变回执完成顺序，关联依靠 ID，不能依靠列表位置。

<a id="p05-a4"></a>
## A4：反思结果不是任务结果

execution 给出候选答案，reflection 给出反馈，refinement 给出改进答案。评审“无需改进”时，框架把最近 execution 设为最终答案；否则容易返回一段评审意见却丢掉用户需要的产物。

本实现通过中英文子串识别“无需改进”，这是目标的实际启发式规则，不是严格语义判定。Memory 是本次轨迹列表，每轮任务重置；P15 的长期 MemoryStore 属于另一个机制。反思阶段内容被标成 THINKING 展示事件，也不等于泄露服务商私有推理字段。

<a id="p05-a5"></a>
## A5：结构化计划仍需校验

Schema 提供生成约束，不能保证模型真的返回正确计划。Planner 仍检查调用数量/名称、参数类型、空步骤和停止原因。失败时停止，比带着不完整步骤继续操作更符合可解释的执行契约。

规划默认 tool_choice=auto，以兼容未支持强制选择的服务商；业务工具的 required/指定名称只属于执行阶段。`5a19188` 的本地 diff 将旧 ReAct 的 tc.function.name/arguments 改成统一 tc.name/arguments，说明策略应消费框架 DTO，不能依赖原始 SDK 对象形状。

<a id="p05-a6"></a>
## A6：计划与真实执行证据要一起保留

PlanSolve._run_loop 不调用 Executor.execute 再开启一套外层生命周期，而是使用 Executor.step_prompt，自己在当前任务内逐步调用共享 turn_events。finally 把本步新交互并回父工作消息，取消也不会丢掉已取得工具证据。

独立 Executor.execute 是另一种便利入口，每步创建借用模型/Registry 的 SimpleAgent，并要求该步 completed。系统提示不是相互覆盖：执行器角色加入前面，调用者已有系统消息保留。规划步骤数、模型调用次数、工具请求次数分别表达不同统计。

工具调用统计还可能包含控制工具或错误/未执行请求的处理回执；它不是纯业务副作用计数。要证明写入恰好一次，必须额外观察实际业务效果。

<a id="p05-a7"></a>
## A7：当前简单工厂足够

create_agent 的 if/elif 只承担构造选择。目标没有动态加载外部策略的需求，因此无需为本阶段引入注册元类、插件发现或依赖注入容器。具体 Agent 继续接受同一组宿主依赖。

同文件的默认子代理工厂会派生配置和 fork 工具目录；它不是完整运行隔离机制。P11 还需要 ToolFilter、子代理作用域、父状态恢复等验证。当前默认关闭，不在 P05 提前声称安全隔离。

<a id="p05-a8"></a>
## A8：共同矩阵与策略专属用例互补

四策略×四入口的 16 个场景证明真实工具往返复用同一语义；控制混批、并发失败、反思和坏计划说明各策略特有行为。只测共同矩阵会漏掉阶段边界，只测特有行为又会漏掉入口漂移。

当前新增策略文件按固定目标实现，不为教学重新设计架构；选择依据和历史对照留在文档。讲解验收：哪些规则放 Runtime，哪些留策略？含 Finish 为什么串行？反思与长期记忆如何区分？计划有效为何仍不代表任务已完成？
