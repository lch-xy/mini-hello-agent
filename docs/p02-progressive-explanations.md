# P02 设计决策详解：执行入口、接入适配与状态边界

按[正文 A1～A8](p02-progressive-guide.md)阅读。本篇围绕架构选择，不逐项拆解函数实现。代码以固定快照为准，设计解释不推断作者未记录的动机。

<a id="p02-a1"></a>
## A1：为什么执行工具需要独立边界

P01 统一的是模型协议，P02 统一的是本地能力接入。两者一起出现，但变化来源不同：升级模型 SDK 不应迫使业务工具改写，增加一个业务工具也不应要求修改模型适配器。

运行层只应处理“调用哪个工具、传什么参数、如何继续”。注册表负责名称到实现的映射，并在真正执行前组合宿主策略和可用性规则。这样可以让不同 Agent 共用同一执行机制。

替代方案是每个 Agent 自己维护函数表。原型很快，但会把策略、异步处理、错误包装和目录冲突扩散到多个 Agent。当前目标需要多策略与组合，选择共享工具层更符合需求。

<a id="p02-a2"></a>
## A2：注册表不是工厂，也不是自动注入容器

ToolRegistry 接收已经创建的 Tool 或 callable。它决定名称是否可注册、如何查询和调用，不负责构造所有业务依赖。业务工具需要数据库或宿主能力时，由宿主创建并传入。

仅支持函数最简单，但结构化描述和多操作接入会产生额外约定。仅支持 Tool 又会增加简单函数的包装成本。目标保留对象、单输入函数和 action 三条来源，在统一入口中明确适配。

目录唯一性属于注册表责任。先验证全部展开项，再更新映射，避免调用者看见半套已注册能力。显式 replace 表达替换意图，默认冲突拒绝，不能因后注册而无声隐藏旧工具。

<a id="p02-a3"></a>
## A3：模型描述和执行结果为什么分别建模

Schema 是调用能力的描述；ToolResponse 是实际执行的证据。描述宣称某参数必需，不等于工具执行层已经做了全面 JSON Schema 校验。结果为 success，也不等于整个用户任务完成。

回执使用三种状态，保留 text 与结构化 data 两种视角。消费方可以向模型展示完整来源、部分结果和错误，也可以记录统计。若只保留 str(result)，后续恢复和观察会失去结构。

显式 JSON Schema 和 action 生成器保留嵌套结构，避免调用方为每种工具手写字符串参数约定。相应代价是维护 Schema 生成与运行签名之间的一致性；目标的运行校验程度依调用路径不同，需要如实记录。

<a id="p02-a4"></a>
## A4：模式与职责怎样配合

| 做法 | 实际协作 | 解释边界 |
| --- | --- | --- |
| Command 风格对象 | Tool 统一接收参数、执行并返回回执 | 目标没有为此实现撤销、队列等完整命令框架 |
| Adapter | AutoGeneratedTool 将绑定方法适配成 Tool | 生成器包装方法，装饰器本身主要标记元数据 |
| Registry | 名称查找、冲突与接入管理 | 不等于创建所有实例的工厂 |
| Policy 策略 | 宿主 callable 返回 PermissionDecision | 执行授权，不等于 Prompt 指令或 OS 沙箱 |
| Circuit Breaker | 连续失败后暂时阻止调用 | 目标没有 half-open 与并发准入事务 |

高内聚体现为具体 Tool 持有业务规则、Registry 持有目录和调度规则、Policy 持有宿主决策。低耦合体现为新增工具不需要修改 SDK，改许可名单不需要修改业务计算。

Registry 的同步/异步方法都组织策略、熔断和执行，它们存在共同规则，但复刻保持目标结构，不为减少表面重复新增一个调度框架。

<a id="p02-a5"></a>
## A5：计算器为什么适合验证纵向设计

它不依赖外部服务，输入和输出确定，能同时验证描述、参数、业务失败和结构化结果。普通函数恒定返回成功无法验证这一整条边界。

目标计算器支持有限 AST 节点与函数名称，不使用任意 Python eval。该限制约束表达式形状，不是完整资源沙箱，也不提供所有数值规模的计算限额。

执行计时在公共包装中，计算逻辑留在具体 Tool。以后增加网络检索或文件工具，计时与错误回执契约可以复用，而业务操作独立变化。

<a id="p02-a6"></a>
## A6：统一入口为何仍保留不同调用约定

Tool 接收参数字典；register_function 保留历史单 input 约定；action 依据方法签名使用 kwargs。强行把普通函数全部改成多参数自动展开，会改变既有函数契约，也混淆描述生成与调用适配。

action 采用签名和 TypeAdapter 生成 Schema，可以保留嵌套模型、数组、枚举和引用。生成前无法解析类型或描述失败，就拒绝注册，不以空 Schema 伪装成功。

同步入口不能把 coroutine 当成结果文本；异步入口需要真正 await 原生异步实现。同步工作移到线程以避免阻塞事件循环，但取消等待不保证工作线程停止，这项运行收尾在后续阶段继续处理。

<a id="p02-a7"></a>
## A7：授权、可用性与隔离是不同问题

授权回答“宿主是否允许本次操作”；熔断回答“该工具最近是否持续失败”；过滤目录回答“本次任务能够查到哪些名称”。一个问题的答案不能代替另一个。

授权拒绝直接返回，不累计服务失败。Policy 发生异常、返回不合法结果或给出 awaitable 时也拒绝，异步审批由宿主先解决。需要策略时先快照执行载荷，再把另一份副本交给策略，避免策略或调用者改掉已授权输入。

fork 复制目录和读取缓存，但共享工具实例、Policy、CircuitBreaker。子表注册/删除不会修改父表映射；工具内部状态和外部副作用依然共享。子表调用失败会改变共享熔断状态，注销同名工具也会触及该状态。它不是深度隔离的沙箱。

Config 中熔断字段不会自动重新创建现有 Registry 的 breaker。调整策略通过显式实例注入；字段存在与实际装配分开核查。

<a id="p02-a8"></a>
## A8：验收应观察哪些架构证据

| 验证来源 | 证明的边界 |
| --- | --- |
| test_tool_response_protocol.py | 回执、错误码、计算器、注册表包装 |
| test_custom_tools.py | 对象、函数与展开工具接入 |
| test_circuit_breaker.py | 熔断状态与执行集成 |
| test_pydantic_v2_serialization.py | 工具描述序列化契约 |
| test_p02_tool_contract.py | 原综合测试中的当前阶段 Schema、注册、fork、异步断言 |
| test_p02_tool_policy.py | 原策略测试中不依赖 Agent 的拒绝、快照与共享策略断言 |

后两份保留所选函数、装饰器和辅助类原文，仅缩小顶层依赖；原文件中涉及文件、Skills、Task、检索的用例在对应阶段接通。不会削弱断言使尚未实现的能力假通过。

阶段验证命令：

```bash
.venv/bin/python -m pytest -q -p no:cacheprovider \
  tests/test_tool_response_protocol.py tests/test_custom_tools.py \
  tests/test_circuit_breaker.py tests/test_pydantic_v2_serialization.py \
  tests/test_p02_tool_contract.py tests/test_p02_tool_policy.py
```

同时回归 P01 非流式范围，保证新增工具层不会改变模型层输入、响应或客户端生命周期。实现结果保存在[阶段记录](p02-learning-record.md)，不将测试通过当作你已掌握架构的证明。

### 当前边界与下一阶段

工具参数校验不是全局严格验证器；Policy 不是 OS 沙箱；熔断不是已启动工作取消器；fork 不是事务；Calculator 不提供通用代码执行。P03 使用这些真实契约组织工具往返，P04 才补完整异步/流式运行收尾。
