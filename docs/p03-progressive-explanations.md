# P03 设计详解：共享循环、工作状态和执行证据

配套[架构正文](p03-progressive-guide.md)。解释设计选择，不把阶段推进变成逐行阅读。

<a id="p03-a1"></a>
## A1：运行层为什么独立于模型与工具层

模型层告诉框架“生成了什么”，工具层告诉框架“执行得到什么”，运行层决定“下一步是什么”。如果 SDK Runner 接管循环，P02 的宿主策略、回执和恢复规则就需要与另一套运行语义整合；如果每个 Agent 自写循环，同一安全与状态约定又会重复。

本项目选择本地共享 Runtime。控制权由 runtime.turn_events 的实际分支证明，而不是由 SimpleAgent 或 SDK 的名称推断。

<a id="p03-a2"></a>
## A2：内部事件源解决的是执行语义复用

同步函数、异步函数和生成器有不同消费方式，但应执行相同业务操作。以异步内部事件源为共同机制，同步入口通过桥接消费，异步入口直接消费，流式入口把可展示事件向外传递。

代价是要管理生成器关闭、事件循环和清理顺序。只写三份相似循环可以更快做出表面接口，却使完成/失败/取消的行为逐渐不一致。目标通过共享执行源承受这项复杂性。

内部字典事件与公开 StreamEvent 是相邻但不同的契约；它们不是跨进程消息总线，也不自动提供生产者背压。

<a id="p03-a3"></a>
## A3：为何保存完整工具关系

一次调用的工作消息会不断追加，长期历史需要在明确边界提交。若历史只存公开答案，下一轮不知道工具是否已执行、哪个回执对应哪个请求，还会丢掉模型需要的原生协议字段。

因此 Message 保存内容供文本使用，同时在 metadata 保留 model_message。输入构建时优先重放原生结构；摘要则按内部策略转换，不把历史参考提升成系统指令。

RunResult 单独记录本次答案、状态、停止原因和调用统计，避免用“有字符串”推断完成。这些状态由运行器更新，历史由生命周期提交，工具资源留在注册表。

<a id="p03-a4"></a>
## A4：哪些耦合是必要协作

Runtime 需要 Agent 提供工具描述、上下文准备和实际工具调度。它不直接理解 SDK 响应层级，也不直接操作每种工具的业务对象；这让协议与工具扩展分别留在 P01/P02。

SimpleAgent._events 包裹策略循环并负责提交、错误、公开事件和清理。后续策略可以覆写 _run_loop 组织反思或计划，复用外层生命周期。它具有模板式扩展点，但不需要额外引入一个模板类或策略注册框架。

目标的 Agent 基类与组件模块存在实际依赖，需要构造历史、计数和截断，也直接引用可选模块。当前先按目标落地依赖，不为了更漂亮的分层改写构造协议。

<a id="p03-a5"></a>
## A5：最小闭环怎样提供强证据

脚本模型能确定地安排第一次工具意图、第二次公开答案；函数实际修改一个可观察的本地列表。测试同时检查函数只执行一次、模型请求两次、第二次确实包含回执、历史保存完整配对，以及统计相加。

恒定返回“成功”的 Agent 替身不能证明这条协作。只看最终文本也不能证明实际执行了工具，因为同样文本可以由模型直接生成。

本阶段复制目标的真实 Runtime、SimpleAgent 与必要依赖，预算仅预定义 BudgetExceeded 异常。SessionStore、TraceLogger、SkillLoader 和完整上下文模块因导入/构造依赖先存在，后续对应阶段仍要进行专门实现范围与契约审查。

<a id="p03-a6"></a>
## A6：失败分层如何决定能否继续

坏参数可以转为 tool 观察供模型纠正；重复身份会破坏回执关联，应在任何副作用前拒绝；模型或运行错误需要传播，不能伪装普通回答。失败类型相近，不表示它们应走同一个处理分支。

轮次上限控制的是工具迭代，不等于总模型调用数。目标在上限后去掉工具与 tool_choice，允许最后总结，但 RunResult 仍标记 max_iterations。输出截断则在工具执行之前停止，避免运行不完整参数。

这些约定同时影响调用次数、模型消息和状态，因此原始测试用这三者共同检查，而不是仅比较答案字符串。

<a id="p03-a7"></a>
## A7：恢复的前提是区分失败与未知

收到工具结果就保存对应回执。线程工作中断等待、网络失联或生成器关闭时，外部操作可能已经发生；没有回执只证明框架尚未确认，不能自动重试写入。

目标收尾会补齐未知结果，尽量使历史保留可解释的工具关系。P03 保留此结构，完整取消与副作用边界在 P04、文件行为在 P08、保存恢复在 P09 验证。

共享模型可被多个独立 Agent 使用，但一个 Agent 的可变历史只能由一次运行推进。宿主资源所有权与会话状态隔离是不同层次。
