# P11 设计详解：局部状态作用域与共享对象图

配套[架构正文](p11-progressive-guide.md)。本实现提供本地子会话，不包含分布式调度或操作系统级隔离。

<a id="p11-a1"></a>
## A1：独立任务对象与临时会话是两层机制

Task 的默认工厂创建新 Agent，避免活跃父对象被同时改历史。run_as_subagent 还用作用域建立空历史和临时元数据，结束后恢复该对象原状态；直接复用只能针对空闲对象。

父模型得到 Task 摘要与 metadata，子模型内部 Read 等完整轨迹留在子会话。摘要是信息压缩，不能替代原始回执做所有事实判断；子任务效果仍要看实际执行和完成状态。

<a id="p11-a2"></a>
## A2：过滤器是工具名称能力的策略

ReadOnly 白名单对新增未知工具默认拒绝，FullAccess 禁止列表对未知名称默认允许；CustomFilter 显式选择策略。过滤器不检查工具实现，一个名字看似只读的工具仍可能产生副作用。

Registry.fork 将对象工具和函数工具一起筛选，避免只删除 _tools 却留下同名函数路径。Policy 与 breaker 仍共享，过滤不会绕过实际 Registry 执行前的宿主许可。

<a id="p11-a3"></a>
## A3：装配顺序决定最终工具目录

默认工厂先复制 Config 并排除控制工具，但只关闭 subagent_enabled/auto_save_enabled；其他 feature 开关沿用。构造子 Agent 会再次 register_default_tools，所以开启 TodoWrite 等时可能得到一个新的同名默认工具。

因此“初始 fork 排除四个名字”不能扩大成“子代理永远没有它们”。运行时 Task 的 tool_filter 再决定临时会话目录。真实用例验证了 TodoWrite 被重新装配，同时父函数定义保持。

<a id="p11-a4"></a>
## A4：finally 恢复的是明确状态白名单

作用域先验证过滤器并准备新 Registry，避免失败后已经清空父历史。history 保存的是 Message 引用列表，metadata 深复制；指定控制字段和原对象身份在 finally 恢复。自定义历史组件收尾失败时，也继续恢复控制字段。

它没有深复制全部 Agent、所有策略局部字段或工具依赖图。session_store 暂设 None 阻止普通保存路径覆盖父文件，外部工具实例或宿主持有资源仍然存在。活动对象拒绝进入，不能把作用域当成可并发重入锁。

<a id="p11-a5"></a>
## A5：参数准入与执行结果分层

Task 在工厂前拒绝未知过滤策略，避免失败降级为无限制。运行成功/未完成分别返回 success/partial，异常再按参数或执行错误区分；partial 不代表外部效果已撤销。

run_as_subagent 使用 last_run.status 判断当前真实 Agent，兼容没有 last_run 的旧自定义对象。metadata 的 steps 和 tokens 仍为历史/字符估算，不等于精确 SDK 调用数和服务 usage；不要混同 P18 的共享预算计量。

<a id="p11-a6"></a>
## A6：嵌套执行仍遵循宿主资源所有权

Task 是同步 Tool，异步 Registry 使用线程接入；子 run 的同步桥接在该线程工作，所以不违反 P04 的活动事件循环限制。线程取消仍有晚到副作用边界，子任务不是可强制杀死的独立进程。

subagent_use_light_llm 开启才使用完整注入的 subagent_llm；关闭时继续主模型，即使注入对象存在。默认没有独立配置时复用主模型。两者均由宿主最终关闭，框架不会在一次 Task 后销毁它们。

<a id="p11-a7"></a>
## A7：容器副本不等于对象图隔离

fork 的读取缓存字典是独立副本，但同一个 ReadTool 可能持有原 Registry。子任务调用它时，Read.run 仍通过 self.registry 写进原缓存；独立映射没有重定向对象内部引用。

真实嵌套测试保留这种父引用并观察父缓存更新，同时验证子字典身份不同、父工具目录与父消息不被子 Read 轨迹替换。该行为按目标保持，没有擅自重绑定工具对象。共享工具中的状态、客户端与外部文件同样不能假设被回滚。
